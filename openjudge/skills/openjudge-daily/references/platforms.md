# Platform editions

## Xiaohongshu

Produce two Chinese title choices, one complete post, one discussion question, a small relevant hashtag set, and exactly six card scripts by default. Prefer short titles, roughly 20 Chinese characters, and a 400–700-character body when the story fits. These are editorial targets, not asserted platform limits.

| Card | Content |
|---|---|
| 1 | Hook, paper identifier, and any qualification needed to interpret the hook |
| 2 | What the paper tries to do, in plain language |
| 3 | The review disagreement or objection, attributed precisely |
| 4 | The author response and what it does or does not resolve |
| 5 | Decision, AC reasoning, and the consequential turn |
| 6 | Editorial punchline, open question, source index, and evidence scope |

If source material cannot support a card's normal role, write a concise "record unavailable" panel and explain what cannot be concluded; do not invent an author response or technical description. Each card script includes a headline, body, source IDs, and visual direction. Label scripts as scripts, not rendered images.

## X

Write a native English thread, normally four to six posts. Keep each post near or below 240 characters as a conservative editorial target, accounting for numbering and links when counting. Use an available official platform counter or documented rules for definitive limit validation. If no authoritative counter is available, report the check as approximate.

The opening carries the hook, the paper identifier, and material scope/context. Later posts explain the disagreement, response, decision, and interpretation. Include accessible evidence links. Do not depend on an unsupported claim about the platform's recommendation algorithm to decide link placement.

For a requested single-post version, make the qualification and link fit or narrow the claim. Do not hide indispensable context in an unposted follow-up.

## OpenJudge evidence page

Write English prose under: the hook, the paper, the timeline, the disagreement, the response and decision, our interpretation, what remains uncertain, sources, and corrections. Facts and interpretation should be visibly distinguishable. Preserve the primary research topic and add a secondary story category.

Produce page content as a file unless the user asks to update the live site. A saved Markdown page is not a deployed website. Use the host's site skill/tool for actual site modifications.

## Visual identity

Use black and warm-white surfaces, one red accent, large readable numbers, and short monospaced edition/status labels. Keep one point per card and generous spacing. Provide consistent source footers and usable phone-scale text.

Use actual source captures or exact text typesetting for documentary evidence. Use image generation for requested original illustrations, mascots, or decorative covers; never use it to invent evidence. Inspect rendered cards before calling them finished. Honor reduced-motion preferences for web motion.

## Output completeness

A `/daily` package contains all of: case brief, source record, two Chinese titles, complete Chinese copy, six card scripts, complete English thread, English evidence page, claim checks, and a resumable handoff. A request for only one route produces that route's output plus the minimum source/status record needed to use it honestly.
