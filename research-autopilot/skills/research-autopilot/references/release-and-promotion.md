# Public releases and academic communication

Use actual source artifacts and allowed claims. Release preparation can proceed
under a design/build request; writing emails or posts does not authorize sending.
Honor already requested publication scope without redundant confirmation.

## A01 GitHub reproducible release

Resolve named repo/account/branch/commit and actual visibility. Provide concise
README with task, supported claims, install/run/evaluate commands, environment,
data/model access, expected outputs and limitations. Include license, citation,
configs, sample commands, reproduction scripts and figure/table source. Separate
private data/secrets from release files. Tag code/results correspondence, changelog
and known issues. Verify a clean run when feasible, disclose untested steps.
Publish only the actual scoped release; retain tag/commit/URL/receipt. Manage issues
with evidence, reproduction conditions, fix/version and affected claims.

## A02 Hugging Face assets

Use applicable hf-cli, dataset, Gradio or paper-publisher skill when installed and
available. Record repo IDs/revisions, licenses/access and model/dataset/Space
relationships. Cards specify purpose, data, evaluation protocol, limitations,
usage, hardware and provenance. Distinguish model weights, dataset files and demo
inference from static results. Check hosted cost/access before launching services.
Uploading code or opening a repo is not publishing evaluated model performance.
Retain actual upload revision/status and test public downloads within scope.

## A03 arXiv and account handoff

Prepare source/PDF, bibliography, figures, title/abstract, authors/order, category,
comments, license choice and cross-links. Check current arXiv instructions and
compile in an appropriate clean environment. Avoid local absolute paths, missing
files and unsupported bibliography assumptions. Record exact paper version.

Public reading and metadata checks need no author login. Submission/replacement
may require account ownership, endorsement, author/license/category choices and
portal checks. Prefer a supported authorized connector; for UI work follow actual
browser/account handoff capabilities. Prepare a concrete upload-ready package and
short human checklist when the portal is complex or author confirmation is needed.
Never request passwords/tokens in chat or claim untested login works. A final
human click is an acceptable workflow. Record portal status and announced arXiv
ID/version; a saved draft is not a public announcement. Replacements retain older
versions; verify final-publication DOI/journal-ref separately.

## A04 Unified release manifest

Link paper/version, code/tag, data/model/revision, demo/site/version, figures,
metric protocol, supported claims, licenses, release date and actual status.
Unknown/missing assets stay explicit. Prefer immutable links and bidirectional
paper/code/model/site references. Allow releasing a usable skill/workflow without
asserting every planned adapter or autonomous laboratory is implemented.

## A05 Public feedback and corrections

Triage external replication reports by exact versions, commands, environment and
scope. Preserve raw discrepancy before diagnosing. Reopen affected claim evidence,
fix or disclose limits, and propagate correction to code/card/paper/site/posts.
Keep old release identities and correction dates. Do not silently rewrite prior
claims. Evidence-backed community feedback enters L/X and the project register.

## C02 Poster, talk, images and video

Start from audience, supported takeaway and actual figures. Allocate a poster or
talk around question → method/insight → key evidence → boundary → artifact link.
Video needs a short script/storyboard, narration, timing, readable captions and
source-to-frame mapping. Use image/video generation only for conceptual visuals;
use exact plots for numbers and exact vectors for topology/equations. Keep editable
source and accessible text. Clearly distinguish recorded demo, teaching example
and live inference. Match every headline to W/V evidence and release identity.

## C03 X, LinkedIn and 小红书

Produce platform-specific draft text and assets from one verified release brief.
X: concise question/result hook, one concrete example, source/artifact link and
optional short thread. LinkedIn: purpose, contributor credit, useful evidence and
how to try it. 小红书: clear Chinese title, approachable problem/story, readable
cards/tutorial and precise limits. No fabricated impact, guarantees, quote,
endorsement or distinction. Preserve public vs author-reported results in wording.
Use requested writing/image skills when relevant. Draft preview and final publish
are distinct; posting requires actual instructed scope/account. Retain URL/receipt,
time/version and follow-up/correction record. Do not automate unsolicited engagement.

## C04 Academic contact and email

Identify recipients from genuinely related papers/labs/resources and verify
identity/contact on official profiles. Explain why each person is relevant and
what specific question/collaboration is offered. Use resolve-recipients if sending
is actually instructed. Prepare a short personalized email with task-specific
subject, honest relation, one useful contribution, evidence link and a clear ask.
Do not invent familiarity, scrape for mass outreach or send without instructions.
If requested, retain sender/recipient, exact text, real receipt and agreed follow-up.

## C05 Founder homepage and research record

Use human-provided founder identity and mission, verified project releases and
paper statuses. Do not fabricate first-ever claims, affiliations, team employment
or adoption metrics. Separate mission/vision, published architecture, usable skills
and future execution integrations. Preserve valuable publication/archive links
when replacing a bio. A model-member page represents proposed configurable roles,
not hired people or connected services. Update homepage/CV/knowledge record from
actual evidence with date/source and manual editing path. Scientific research
access can be framed as the founder's motivation without claiming all historical
research was restricted to a single class of people.
