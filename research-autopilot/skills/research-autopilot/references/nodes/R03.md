# R03 回应策略和补实验优先级

这是 research-autopilot 的内部节点 skill 入口。

## 状态与任务契约

- 内容状态：自有规范详细覆盖。
- 输入：问题台账与讨论时间
- 输出：rebuttal 证据计划
- 验收：先解决改变判断的关键问题；已够证据的项只做澄清。
- 版本：1.1.0

## 使用自有规范

1. 核对实际材料、版本、当前决策与已授权范围，延续已有研究。
2. 用 `python3 scripts/research_nodes.py show R03` 逐段核验并加载以下原文。来源变化先核对，保留旧版本。
3. 按输入、输出和验收交付；操作规范、实际回执与科学证据分别记录。

## 实际能力与验证

绑定校验只证明规范可定位。实际运行、任务验收、外部操作和科研主张须分别保存证据。尚未连接的项目调度器、GPU 或账号服务不能登记为已实现。

## 小点之间的交接

按真实任务选择边的条件。E 区执行/修复返回实际调用节点及任务身份；84 点和 221 边不新增合法状态机 route/phase/gate。

| 到节点 | 关系 | 条件 | 交付内容 |
|---|---|---|---|
| G01 | 分支 | 回应需要一个决定性的最小对照 | 评审问题和补证据义务 |
| V02 | 分支 | 回应需要基线或重复验证 | 审稿相关的冻结补实验任务 |
| V03 | 分支 | 回应需要机制或消融证据 | 审稿相关的机制验证任务 |
| V04 | 分支 | 回应需要泛化或边界证据 | 审稿相关的范围验证任务 |
| L03 | 分支 | 回应需要精读或核对被指出的工作 | 评审指向的论断和来源 |
| W05 | 分支 | 问题属于局部表达或定义澄清 | 受影响段落及修改职责 |
| R04 | 输入 | 回应方案与必要证据已有可审计结果 | 逐条回应计划；未解决项如实标明 |
