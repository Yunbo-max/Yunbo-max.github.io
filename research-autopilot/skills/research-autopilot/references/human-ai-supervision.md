# Human–AI research supervision

Use for P/I and for a changed goal, priority, resource constraint or preference.
The human defines value and acceptable tradeoffs; evidence defines what can be
claimed. This is a shared supervisor across projects. A supervisor specification
does not imply an installed scheduler, connected accounts or available compute.

## P01 Goals and portfolio

Maintain a project register with stable project ID, human goal, current decision,
origin, milestone, assets, obligations, next action and dependencies. Separate
scientific outcome, publication outcome, learning and public communication. A
negative finding, useful dataset, replication or stopped project can meet a goal.
Record each preference with verbatim/source locator, scope, explicit/provisional
status, date, review trigger and superseded version. Do not promote a temporary
choice into a durable personal preference. Do not infer ambitions from affiliation.

Discuss tradeoffs using two or three concrete alternatives, their evidence,
human time, compute, expected information and opportunity cost. Respect existing
authorization; continue routine work instead of requesting the same decision again.

## P02 Assets and current position

Read the actual manuscript, repository, run records and reviews. Record immutable
versions, missing files, inspected scope, last credible milestone and unresolved
obligations. Distinguish author's report, observed output and inference. Resume
from these assets rather than resetting to a topic interview. Return completed
node outputs to the project register with evidence identity and next action.

## P03 Priorities and work in progress

Ask how the human values deadline, scientific importance, uncertainty reduction,
learning, collaboration and visibility. Present a transparent priority rationale;
never silently optimize publication count. Track active, waiting, paused and
completed work separately. Set a human-agreed WIP limit and revisit it on a real
conflict. Give each active project one decision-driving next action. Do not count
GPU waiting as human work. New priorities version the plan rather than erase it.

## P04 Resources and people

Maintain availability/reservations for human time, GPU memory and device IDs,
CPU/RAM, storage, wall time, API budget and collaborator responsibilities. A
planned reservation is not a running job. Resolve clashes using alternatives:
queue, reduce the pilot, switch qualified assets, or reprioritize with the human.
Map S choices and E jobs back to the project goal and resource envelope. Record
actual job IDs and costs; cannot promise availability from a model's memory.
Discuss scope/credit/responsibility changes with affected humans before committing.

## P05 Growth and retrospectives

After a meaningful decision, record what was learned, surprising failures,
transferable knowledge, a skill gap and one practical next learning task. Track
understanding and independent verification rather than number of papers/posts.
Offer doing, explaining and reviewing modes according to the human's preferences.
Keep researcher's private reflections separate from publicly released project data.

## I01 Progressive goal interview

Start by summarizing known goals/assets and the next decision. Use the following
question bank to check completeness, not to ask everything in one turn. Ask at
most three material questions per round; use concise choices and optional free
text. Explain which downstream choice an answer changes. Unknown answers may
remain unknown while independent work continues. Preserve answers across sessions.

| Dimension | Questions to resolve when material |
|---|---|
| Purpose | What should become possible? Who benefits? Is the goal discovery, an application, replication, publication or learning? What would change a decision? |
| Problem | What fails naturally? Under which conditions? How often and with what consequence? What strongest simple solution already works? |
| Starting point | Topic, existing method/results, or rejected manuscript? Which artifacts are authoritative? What has been read, run and independently verified? |
| Contribution | Method, empirical phenomenon, theory, benchmark/data or system? Is a new component necessary? What remains valuable if the method fails? |
| Evidence | Which atomic claim must be established? Which observation would contradict it? What is the task endpoint, unit and evaluator? What confirmation data remain unseen? |
| Feasibility | Available models, data, code and licenses? Human time, GPU/API and storage limits? Existing collaborators and constraints? Minimum decisive affordable test? |
| Delivery | Desired audience/venue/year/track/stage and deadline? Public/private materials? Paper, artifact, website, demo or teaching output? |
| Interaction | Prefer options with recommendations or exploration? How much explanation/learning? Which decisions belong to the human? When should goals be reconsidered? |
| Exit | Minimum success? A reason to stop or pause? A resource ceiling? Which question would remain unresolved if we stop? |

The extended [52-question bank](human-question-bank.md) provides independent,
trigger-based slots across intake, methods, experiments and review.

Return a sourced goal brief, chosen current decision, remaining unknowns and a
small actionable next step. Correct it when the human supplies new information.

## I02 Contribution types

Select a track from available evidence, not a universal method-paper template.
Method: mechanism and fair comparisons; phenomenon: definition, prevalence and
competing explanations; theory: explicit assumptions/proofs/counterexamples;
dataset/benchmark: provenance, validity and coverage; system: end-to-end utility,
cost and failure/recovery. Mixed tracks state which evidence supports each claim.

## I03 Venue and stage

Resolve venue/year/track/article type/stage using current official instructions.
Record template, limits, anonymity, artifact, ethics and discussion-window rules
only when applicable. Explain fit and tradeoffs. Existing rules are not current
merely because they are familiar. A target venue is a goal, not a quality verdict.

## I04 Success and exit

Agree on minimum informative outcome, milestones, budget ceiling and stop/pause
criteria. Distinguish scientific falsification from implementation invalidity.
Review goals on new evidence or changed human circumstances. Publication is not
the sole completion criterion. Goal changes propagate through P, S, G/V and W/C.
